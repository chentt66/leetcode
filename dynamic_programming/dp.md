你这个直觉非常敏锐 —— 而且抓到了一个**很多人学 DP 时都会卡住的真问题**。我来把它讲透。

---

## 你说的那种常见模式是什么

你心里想的应该是这类写法,在背包、LIS、硬币兑换里到处都是:

```python
# 0/1 背包
for i in items:
    for w in range(W, weight[i]-1, -1):
        dp[w] = max(dp[w], dp[w-weight[i]] + value[i])
        #       ^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
        #       旧的自己 vs 选了这个物品的新方案
```

```python
# LIS (O(n²))
for i in range(n):
    for j in range(i):
        if nums[j] < nums[i]:
            dp[i] = max(dp[i], dp[j] + 1)
            #       ^^^^^   ^^^^^^^^^^^
            #       当前最好 vs 接在 j 后面
```

它们共同的形态是:

$$
dp[i] = \max\bigl(\, dp[i],\ \ \text{某个新候选}\,\bigr)
$$

**`dp[i]` 出现在等号两边**,像是在"不断刷新自己"。

---

## 而你这道题是

$$
dp[i] = \max\bigl(\, dp[i-1],\ \ \text{prices}[i] - \text{min\_price}[i]\,\bigr)
$$

**`dp[i]` 只出现在左边**,右边是 `dp[i-1]`。它不"刷新自己",而是"从前一格继承 + 比较一个新选项"。

你觉得奇怪,就是因为这两种**外形不同**。

---

## 关键洞察:它们其实是同一件事

`dp[i] = max(dp[i], xxx)` 这种写法,**翻译过来就是**:

> "`dp[i]` 已经有一个候选值了,现在多一个新候选 `xxx`,取较大的。"

那它**之前的那个值**从哪来的?有两种可能:

### 情况 A:循环外预先填好(显式继承)

很多写法长这样:

```python
for i in range(1, n):
    dp[i] = dp[i-1]              # 第一步:先继承上一格
    for j in ...:
        dp[i] = max(dp[i], ...)  # 第二步:看有没有更好的新方案
```

这其实就是**把"和 `dp[i-1]` 比较"和"和新候选比较"拆成了两行**。

如果合并成一行:
```python
dp[i] = max(dp[i-1], 新候选)
```

—— **就是你这道题的形态**。✅

### 情况 B:多个候选要轮流比较(必须就地刷新)

LIS 的内层循环要遍历所有 $j < i$,产生很多个候选:

```python
for j in range(i):
    if nums[j] < nums[i]:
        dp[i] = max(dp[i], dp[j] + 1)   # j 有很多种取值
```

这里 `dp[i] = max(dp[i], ...)` **不得不就地刷新**,因为有 $i$ 个候选要逐个比较,你没法一行写完。

---

## 所以本质区别是:**候选数量**

| | 候选数量 | 自然写法 |
|---|---|---|
| 121 这题 | **每个 i 只有 2 个候选**:继承 `dp[i-1]`,或今天卖出 | `dp[i] = max(dp[i-1], 新候选)` |
| 背包 | 每个 (i, w) 也只有 2 个候选:不选 i,或选 i | `dp[w] = max(dp[w], dp[w-wi]+vi)`(同上,只是用 `dp[w]` 表示"不选 i 时的值") |
| LIS | 每个 i 有 $i$ 个候选:接在 $0, 1, \dots, i-1$ 后面 | 必须 `dp[i] = max(dp[i], ...)` 在内层循环里刷新 |
| 硬币兑换 | 每个 amount 有 $k$ 个候选(k 种硬币) | 必须 `dp[a] = max/min(dp[a], ...)` 在硬币循环里刷新 |

**当候选只有 2 个时,两种写法等价**:
```python
dp[i] = max(dp[i-1], 新候选)      # 你这版
# 等价于
dp[i] = dp[i-1]                   # 拆成两步
dp[i] = max(dp[i], 新候选)
```

**当候选有多个时,只能用就地刷新写法**,因为没法把多个 `max` 塞进一行。

---

## 再看背包,你会发现它"长得像"但本质相同

```python
dp[w] = max(dp[w], dp[w-weight[i]] + value[i])
```

很多人也卡在"`dp[w]` 出现在两边好奇怪"。其实把它翻译一下:

- 等号右边的 `dp[w]` = "**当前物品不选**" 时的最优值(也就是处理上一个物品后的 `dp[w]`)
- `dp[w-weight[i]] + value[i]` = "**当前物品选**" 时的最优值

所以背包的真实语义是:

$$
dp[i][w] = \max\bigl(\, \underbrace{dp[i-1][w]}_{\text{不选}}, \ \ \underbrace{dp[i-1][w-w_i] + v_i}_{\text{选}} \,\bigr)
$$

—— **和你这道题的形态完全一样**!只不过背包做了滚动数组压缩,把 $dp[i-1][w]$ 直接写成 `dp[w]`(因为上一轮的值还没被覆盖),所以看起来变成了 `dp[w] = max(dp[w], ...)`。

**所以背包那种"奇怪的"写法,本质就是你这道题的写法 + 滚动数组的视觉伪装。**

---

## 一句话总结

> `dp[i] = max(dp[i], xxx)` 不是"另一种 DP 模式",它是 `dp[i] = max(dp[i-1], xxx)` 的两种变形:
> - **多候选** → 必须就地刷新,被迫写成这个样子
> - **滚动数组** → 等号右边的 `dp[i]` 其实是"上一轮的 `dp[i]`",视觉上看起来在刷新自己,实际还是在和"上一层"比较

你这道题候选只有 2 个,又没做滚动数组,所以写出来就是最朴素、最"原汁原味"的 DP 形态。**不是它奇怪,是你之前见的那些都在偷懒压缩**。😄
